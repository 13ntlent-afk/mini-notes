THE WORKFLOW - Step by Step

Step 1: CREATE A BRANCH FOR THE PHASE
────────────────────────────────────────
  git checkout -b phase-1-setup
  
  On branch: phase-1-setup
  Ready to start work!


Step 2: WORK & MAKE MEANINGFUL COMMITS
─────────────────────────────────────────
  git add docker-compose.yml Dockerfile
  git commit -m "feat: [Phase-1] Add Docker configuration
  
  - Create Dockerfile for microservices
  - Add docker-compose.yml with PostgreSQL
  - Configure environment"
  
  Then again...
  
  git add src/
  git commit -m "feat: [Phase-1] Initialize project structure
  
  - Create service directories
  - Add package.json with npm scripts
  - Configure ESLint and Prettier"
  
  And again...
  
  git add .github/workflows/
  git commit -m "ci: [Phase-1] Set up GitHub Actions
  
  - Add lint job
  - Add build job
  - Configure PR checks"


Step 3: VERIFY CHECKPOINT IS COMPLETE
──────────────────────────────────────
  ✓ Run tests:      npm run test
  ✓ Lint code:      npm run lint
  ✓ Build works:    npm run build
  ✓ Docs updated:   README.md
  ✓ No breaking:    Changes compatible


Step 4: TAG THE PHASE ← THE CRITICAL STEP
─────────────────────────────────────────
  git tag -a phase-1 -m "Phase 1 Complete: Infrastructure setup
  
  Completed:
  ✓ Docker containerization
  ✓ Project structure
  ✓ CI/CD pipeline
  ✓ Development docs"
  
  This creates an IMMUTABLE marker that:
  - Timestamps the checkpoint
  - Documents what was completed
  - Allows easy checkout: git checkout phase-1
  - Can be pushed to remote: git push origin phase-1


Step 5: MOVE TO NEXT PHASE
─────────────────────────
  git checkout -b phase-2-database
  
  Continue the cycle...
  Commit → Commit → Commit → TAG → Next Phase

QUICK COMMANDS

Your Daily Commands:
━━━━━━━━━━━━━━━━━━━

# Start a new phase
git checkout -b phase-N-description

# Make a commit (do this 5-10 times per phase)
git commit -m "feat: [Phase-N] Your description

- Bullet points
- Describing changes"

# When phase is complete
git tag -a phase-N -m "Phase N Complete: Description

Completed items"

# See your progress
git log --oneline --graph --all

# View all tags
git tag -l

# See what changed in a phase
git diff phase-1 phase-2 --stat

WHY THIS MATTERS FOR WEEK 5 CHALLENGES

✓ TRACEABILITY
  Every phase is marked with a git tag that shows:
  - Exactly when it was completed
  - What work was done
  - Which commit it points to

✓ MEANINGFUL HISTORY
  Instead of vague commits like "updates", you have:
  - feat: [Phase-1] Add Docker configuration
  - feat: [Phase-1] Initialize project structure
  - ci: [Phase-1] Set up GitHub Actions

✓ CHECKPOINTS
  Tags create natural stopping points where you verify:
  - All tests pass
  - Code is documented
  - No breaking changes
  - Ready for next phase

✓ PROFESSIONAL WORKFLOW
  This demonstrates:
  - DevOps best practices
  - Semantic versioning
  - Clean commit history
  - Organized development
